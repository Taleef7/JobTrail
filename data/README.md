# data/

Evaluation data for JobTrail v2. Training data (3–5k synthetic examples) is published to Hugging Face Datasets, not stored here.

## Files (arrive in M1)

| File                       | What                                                                   | Created in |
| -------------------------- | ---------------------------------------------------------------------- | ---------- |
| `scenarios.yaml`           | Scenario matrix: trades × note styles × hard-case tags                 | #70        |
| `drafts/*.jsonl`           | Teacher-drafted notes + labels, **not yet human-verified**             | #70        |
| `test.jsonl`               | Frozen test set (~200), human-verified — never trained or tuned on     | #71        |
| `dev.jsonl`                | Dev set (~100) for iteration and error analysis                        | #71        |
| `matcher-validation.jsonl` | Human pass/fail judgments used to validate the scorer's fuzzy matchers | #68        |
| `FROZEN.md`                | SHA-256 of every frozen file; CI fails if a frozen file changes        | #71        |

## JSONL record format

One JSON object per line:

```json
{
  "id": "t-0001",
  "note": "Swapped the P-trap under the kitchen sink...",
  "gold": { "...": "schema v2 record" },
  "source": "synthetic",
  "tags": ["negation", "hours-phrasing"],
  "verified": true
}
```

- `gold` must validate against the schema v2 JSON Schema generated by `packages/core` (#67).
- `source`: `synthetic` · `role-played-owner` · `role-played-other`. Slices are always reported separately.
- `verified`: `true` only after a human checked every field in the labeling tool.

## Freeze rule

Once `test.jsonl` is frozen, it is never edited. Additions (e.g. the spoken-note slice, #92) go into a **new versioned file**, and the hashes in `FROZEN.md` are extended, not replaced.
